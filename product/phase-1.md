# Phase 1 - brief

## Core invariant requirements

- IR-1: Assess this repository itself against the goals it states for itself.
- IR-2: Base conclusions on observable repository evidence and clearly separate demonstrated behavior from stated intent or untested assumptions.
- IR-3: Identify the highest-impact reasons the repository may or may not achieve those goals, with practical, prioritized recommendations.

## What this is not

- An implementation task or a request to change product code.
- An assessment of an application that might later be produced using this workflow.
- A general security, performance, or market review unless it directly affects achievement of the repository's stated goals.

## For Phase 2

- Confirmed working inference: the subject is the Nose repository and its own documented goals are the primary benchmark.
- Trace each stated goal to the workflow, artifacts, validation mechanisms, and any executable evidence that support or undermine it.
- Establish how to judge goal achievement when a claim has no directly executable check.
- Produce a concise findings-first review with strengths, gaps, risks, and recommendations.

## Parked ideas

- Build an automated workflow-compliance evaluator - this is a separate product from reviewing the current repository.

## Five-whys that changed the core

- A useful review needs a clear benchmark; the current locked product state contains no goal definition, so the repository's stated goals must become the benchmark in the next phase.
